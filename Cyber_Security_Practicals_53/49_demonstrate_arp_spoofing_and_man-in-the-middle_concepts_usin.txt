PRACTICAL NO. 49
DEMONSTRATE ARP SPOOFING AND MAN-IN-THE-MIDDLE CONCEPTS USING BETTERCAP IN AN ISOLATED LAB
==========================================================================================

AIM:
To use Bettercap to demonstrate ARP spoofing and man-in-the-middle (MITM) attack concepts in a fully isolated lab network.

SYSTEM / SOFTWARE / HARDWARE REQUIREMENTS:
  1. Kali Linux with Bettercap installed
  2. Two additional lab VMs (e.g., Windows 10 and Metasploitable 2) on an isolated Host-only network
  3. Wireshark (optional, for traffic verification)

THEORY:
ARP spoofing exploits the lack of authentication in the Address Resolution Protocol by sending forged ARP replies, associating the attacker's MAC address with the IP address of another host (commonly the default gateway). This causes victim traffic to be rerouted through the attacker's machine, enabling a man-in-the-middle position. This technique must only ever be performed in an isolated lab, never on a shared or production network, as it disrupts and intercepts others' traffic.

PROCEDURE:
  1. Confirm all VMs are on an isolated Host-only network with no bridge to production networks.
  2. Identify the IPs of the 'victim' VM and the 'gateway' (or a second VM acting as the target of interception).
  3. Launch Bettercap: sudo bettercap -iface eth0.
  4. Enable network discovery: net.probe on, then list hosts: net.show.
  5. Set the ARP spoofing target: set arp.spoof.targets <victim-IP>.
  6. Start ARP spoofing: arp.spoof on.
  7. Enable traffic sniffing to observe intercepted data: net.sniff on.
  8. From the victim VM, generate some plaintext HTTP traffic and observe it appearing in Bettercap's sniffer output on Kali.
  9. Stop the attack (arp.spoof off) immediately after the demonstration and restore normal ARP tables; document observations and ethical/legal notes.

RESULT:
Bettercap successfully poisoned the ARP cache of the victim machine, repositioning the Kali VM as a man-in-the-middle, and plaintext traffic generated by the victim was observed and captured on the attacker machine.

CONCLUSION:
This controlled demonstration highlights the serious risk ARP spoofing poses to unencrypted network communications, emphasizing the importance of using encrypted protocols (HTTPS, VPNs) and network defenses such as Dynamic ARP Inspection.
